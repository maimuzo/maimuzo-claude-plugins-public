# 15〜30秒の紹介動画を作る流れ

このプラグインは、ある製品の機能紹介動画（1080×1080・30fps・15〜30秒）を何本か作った流れを、どの製品にも使える形にしたもの。
最初の例は、continuo（github.com/maimuzo/continuo）の紹介動画12本で、その制作の記録は github.com/maimuzo/continuo-pr-movie にある。

## 流れ（人間が書いた原文の後ろの6項目）

| 順 | 原文 | スキル | 人間が確認すること |
| --- | --- | --- | --- |
| 1 | 最初に紹介したい内容に関する情報を渡す | `start` | 方針（尺・本数・投稿先・見せ方・色） |
| 2 | 次にコンテの内容を人間とAIが一緒に考える。伝えたい概要を人間がまとめ、それを元にコンテをAIに書いてもらう | `concept-work` | コンテ（全回の秒・何が起きるか・字幕） |
| 3 | そのコンテに必要なキャラクターをcodexやnano bananaに書いてもらう。このcodexやnano bananaに連携する部分もスキルに含む | `characters` | 絵柄とキャラクター |
| 4 | 作ったキャラクターを使って、動画毎にコンテを詳細に決める。この時代表的なシーンをcodexやnano bananaに書いてもらうことで、イメージを固める | `storyboard` | 絵コンテ（構図） |
| 5 | まず1本動画化して、細部を調整する。 | `first-video` | 最初の1本 |
| 6 | 完成したら他の動画を並行して動画化して、全部一気に細部を調整する | `remaining-videos` | 残りの全部 |

公開（release・README への掲載・投稿）は、このプラグインの範囲外。ローカルに mp4 を書き出すところまでを行う。

## 工程の順を守る

- 工程の順は、コンテ → キャラクター → 回ごとの詳しいコンテと絵コンテ → 動画。前の工程が人間に確認される前に、次の工程を並行で作らない。
  （例: 絵コンテを描いている最中に1本目の動画を並行で作り直させたら、構図も動きも合わず、作り直しになった）
- 各スキルは、最初に前の工程の成果物があるかを確かめる。無ければ何もせず、前のスキルを示して止まる。状態を書いたファイルは持たない。
- コンテを直したら、動画もそのコンテで作り直すまでが1つの作業。コンテだけ直して動画が古いままだと、人間は動画ができていると思って見に行く。
- 動画がもうある回を直すときは、絵コンテを描き直さない。

## ファイルの置き場所（使う側のリポジトリ）

スキルが作るファイルは、リポジトリ直下の `short_movie/` の下だけに置く。リポジトリ直下の既存のファイルは触らない。
Remotion の土台とスクリプトはプラグインの中にあり、使う側には置かない。

```
short_movie/
├── .gitignore          # out/・inbox/・__pycache__/ を除く
├── brief.md            # 製品の情報と方針（start）
├── theme.json          # 色（start）。書体は土台で M PLUS Rounded 1c に固定
├── concept.md          # 全回のコンテ（concept-work）。回の id の一覧の正
├── characters.md       # キャラクター設定（characters）
├── storyboards/<回のid>.md      # 回ごとの詳しいコンテ（storyboard）
├── videos/<回のid>/    # index.tsx・script.ts・その回だけの部品（first-video・remaining-videos）
├── videos/_shared/     # この製品の全部の回で使う部品の直し
├── materials/
│   ├── prompts/        # 絵の依頼文。どちらの道具で描いたかも書く
│   ├── raw/            # 描かせたままの絵
│   ├── ref/            # 設定画（毎回添付する正の絵）
│   ├── characters/ props/ backgrounds/ ep/<回のid>/   # 動画で使う絵
│   ├── storyboards/<回のid>/   # 絵コンテの絵
│   └── sfx/            # wav・make_sfx.py の写し・sfx_<回のid>.py・README.md
├── inbox/              # Nano Banana の絵の受け取り口（git に入れない）
└── out/                # mp4・コマ割りの一覧・作業の記録（git に入れない）
```

残すかどうかは「作り直すときに手間がかかるか」で決める。手間がかかるものは、中間ファイルと、それを作ったコードの写しまで全部残す。
mp4・コマ割りの一覧・作業場所・node_modules は、残したものからコマンド1つで作り直せるので残さない。

## 回の決まり

- 回の id はケバブ（英小文字・数字・ハイフン）の1つ。フォルダ名・`meta.id`・スキルの引数・効果音のファイル名で同じ id を使う（Remotion の Composition の id は `_` を使えない）。
- `videos/<回のid>/script.ts` が `meta = { id, durationInSeconds }` と場面の表を持ち、`index.tsx` が `default` で回の部品を、`meta` を re-export する。雛形は `references/video-template/`。
- 尺は15〜30秒。タイトルは頭の2秒、締めは終わりの2秒（30秒の回は3秒）を目安に、`script.ts` の場面の表で決める。最後の場面の `to` は `meta` の尺と同じにする（`render.sh` が確かめる）。
- 回をまたいで import してよいのは `videos/_shared/` だけ。製品全体で効かせたい部品の直しは、土台の部品を `_shared/` へ写して直し、`../theme` の import を `../../theme` に書き換える。
