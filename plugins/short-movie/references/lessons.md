# 人間から受けた指摘（どの製品の動画にも効くもの）

最初の例（continuo の紹介動画）で人間から受けた指摘のうち、どの製品にも当てはまるものを集めた。
例に出てくる名前（continuo・コンティ・回の呼び名）は例であって、手順ではない。

## 中身の作り方

- 役の関係は、実物の関係のとおりに見せる。
  （例: continuo が Codex に作業を渡すことはなく、Claude Code が Codex に頼む。指示を出すのは continuo ではなく issue のコメント）
- 紹介するものの機能ではないものを描かない。
  （例: 別の端末から見られるのは Claude Code 自体の機能で、continuo の機能ではないので、場面ごと外した）
- 何を表す絵かが読み取れないものには、看板を付ける。比べるものは同じ大きさにそろえる。
- 左右で比べる場面は、左右の看板を字幕より目立たせる。
- 字幕の言い方は、読む人が使う言葉にする。（例: 「枠」ではなく「レートリミット」、「札」ではなく「Role」）
- 架空の名前は、一目で別物と分かる名前にする。（例: リポジトリ名 `owner/project-a`）
- コンテに無い字（看板・札）を足さない。足したら報告する。
- 名前の札はキャラクターの頭の上に出す。2体並ぶ場面では2体とも出す（胸の名札は小さくて読めなかった）。
- 人物は可愛い顔にする。顔をつぶしたり歪めたりしない。喜ぶ場面で変な顔にならないよう、表情の絵を描き分ける。
- 実物にない動きを絵にしない。（例: 「パソコンで書いたものを手で丸めて投げる」は不自然なので、Enter で紙飛行機が飛ぶ形にした）
- 場面が短すぎて何を表しているか分からないところは延ばす（1秒では足りなかった）。
- 金額のように実物と取り違えられる数字は出さない。
- 既存のキャラクターやロゴ（有名なマスコット、他社のロゴ、玩具のブロックの突起など）に似せない。依頼文にも既存のキャラクター名・ロゴ名を書かない。

## 人間への報告の仕方

- 回は番号ではなく呼び名で指す（「6本目」ではなく「チームで入札の回」）。
- 測っていないことは「測っていない」と書く。耳で聞いていない音は「聞いていない」と書く（AI は音を聞けない。人間に聞いてもらう）。
